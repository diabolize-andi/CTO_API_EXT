Flight Push integration

Receiving flights from Click & Take off

Overview

Click & Take off (CTO) can send an eligible club flight to a URL supplied by the receiving platform after the flight is created. The receiver provides the HTTPS endpoint, an optional bearer token, and the desired full-flight or segment mode. The optional position export is configured separately.

Push request

PUT https://receiver.example.com/flights
Content-Type: application/json
Authorization: Bearer <token>  (only when configured)

The JSON body is an object containing a data array. In full-flight mode it contains the exported flight; in segment mode it contains its exported segments. One request can therefore contain multiple segments belonging to the same flight.

{

      "deviceId": 42,

      "endTime": "2026-10-20T11:00:00Z",
      "startTimeFlight": "2026-10-20T10:05:00Z",
      "endTimeFlight": "2026-10-20T10:55:00Z",
      "icaoAeroStart": "LFFE",
      "icaoAeroEnd": "LFFE",
      "landing": 1
    }
  ]
}
{

    {

The example is illustrative. Optional fields that have no value can be omitted from the JSON; do not assume every flight has an aerodrome, analysis, pilot or instructor.

Time zone: dates are sent in UTC, in ISO 8601 format with the Z suffix.

Fields

FieldDescription
volId, deviceIdInternal identifiers of the flight and device.
clubName, deviceNameClub and aircraft names.
branchNumberSegment number, in segment mode.
startTime, endTimeExported start and end dates. Their selection can depend on the device's external time-export configuration.
startTimeFlight, endTimeFlightAlternative start and end dates when available; also affected by the export mode.
icaoAeroStart, icaoAeroEnd, icaoDeparture, arrival and intermediate aerodrome codes where available. icao is specific to full-flight mode.
hourMeterStart, hourMeterEnd, hourMeterStartFlight, hourMeterEndFlightTime-related values when available. In segment mode these are timestamps in Unix milliseconds, not conventional hour-meter readings; values can be affected by the export mode.
pilotEmail, instructorEmailAssignment emails when known; they may be absent from a newly created flight.
landingNumber of landings when analysis is available; this is a number, not a boolean.
latitude, longitude, altitude, timeOptional parallel position arrays when position export is enabled. The sender samples the first, last and every twentieth position, subject to validity checks.

Receiver response and retries

Return HTTP 200 or 201 to acknowledge receipt. Other status codes, including 204, 404 and 409, are treated as failed deliveries.

Failed flights are eligible for retry by a task scheduled every 10 minutes, while their failure counter is below five. The receiver should handle repeat deliveries safely, including a timeout after it has already processed a request. The sender uses connection and response timeouts of five seconds.

Assigning pilots and instructors

Returning email addresses in the Push response does not create an assignment. To send an assignment back to CTO, use the flight API or the segment API with the appropriate token and the dates expected by those routes.

Alternative: notification-only mode

When configured without flight data, CTO sends a GET to the configured URL instead of the JSON PUT. It adds planeCode and api=clickandtakeoff if the URL does not already contain planeCode=. The same optional bearer authorization and HTTP 200/201 success rules apply. This request has no flight JSON body.
